# 2026-08-26 — C/Lisp build split: per-file config compile + staged temacs

Outcome of the dynamic-derivations research arc (deep-research runs on RFC 92
and on the pdumper): dynamic derivations stay a watch item (experimental,
stabilisation milestone two years overdue, cachix/substituter support missing),
but two things the research surfaced are buildable today and landed on this
branch:

## nix/config-compiled-split.nix — per-file config compile

One derivation per config file instead of the monolithic
`nix/config-compiled.nix` batch. Editing one module recompiles one
derivation (plus init.el's, whose compile executes its requires and
therefore sees all of lisp/). Key facts this rests on:

- The module graph is a star — no `lisp/init-*.el` requires another
  (verified by scan; `init-devenv.el` → `devenv.el` is the one wired
  compile dep). Cross-file symbols use `declare-function`/`defvar` stubs;
  six modules were missing the `jotain-var-file` stub that `init-ai.el`
  already had — added, since a clean per-file session can't rely on the
  batch session having loaded init-core first.
- Each derivation compiles *inside its own $out* and prunes to its own
  files. Verified: the produced `.eln`'s path-hash is exactly
  `md5($out/<file>.el)[:8]`, so realpath through the symlinkJoin resolves
  to the path the eln was hashed against (same Bug#44701 mechanism the
  monolith documents).
- Byte-for-byte parity with the monolith is a *diagnostic*, not a check
  (`just elc-parity`, nix/elc-parity.nix): the monolith's single session
  can leak state (features, defvars, gensym counter) into later files'
  bytecode, so a DIFFERS line is a bug report against lisp/ (usually a
  missing stub), and it must not gate deploys.
- CI gate: `checks.elisp-compile-split` (warnings-as-errors per-file
  build), added to PR CI's named subset next to elisp-compile.

Validated in-session (cachix unreachable here, so with nixpkgs' emacs-nox):
early-init.el per-file byte+native compile, output layout, eln path-hash;
eval-level incrementality both directions (touching init-ai.el leaves
init-org's drvPath unchanged; changes init-ai's and init.el's).

## nix/emacs-staged.nix — two-stage from-source Emacs (experimental)

`stageA` = configure + `make -C lib` + `make -C src temacs` over a
filtered source (everything except `lisp/**/*.el`, keeping `loadup.el` —
src/lisp.mk is generated from it — and `lisp/international/` + admin
charsets, which temacs's Makefile rule depends on). `stageB` = untar the
stage-A build tree (zstd tar keeps the mtimes the store would flatten),
overlay the full source's lisp/ with fresh mtimes, `make epaths-force
prefix=$out` (the fresh epaths.h deliberately recompiles its includers and
relinks temacs), full `make` + `make install prefix=$out`. Contract:
`lispPatches` invalidate only stageB; `cPatches` invalidate both —
verified at eval level. Never CI, not cache-parity; `just build-staged`.

## ca-derivations: where they actually pay

Both files take `contentAddressed ? false`. Verified on Nix 2.34.8 with
`--extra-experimental-features ca-derivations`: building the filtered
stage-A source from a tree with a simulated lisp-only diff produced the
*identical* output path — i.e. under CA, stageA cache-hits across
revision bumps whose diff stays in lisp/. Without CA the split still
gives per-file rebuild granularity, just not cutoff. Off by default,
never enabled in CI.

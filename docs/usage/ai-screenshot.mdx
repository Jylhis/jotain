# AI Screenshots

Jotain can render the current frame to an image file so an AI assistant
(or you) can *see* how Emacs looks. The capture uses the built-in
`x-export-frames`, which draws the frame straight to PNG/SVG/PDF on
cairo builds, with no external screenshot tool. The technique follows
[Automating Emacs Screenshots (Emacs Redux)][article-1].

Two entry points share the same code: an interactive command for live
sessions, and a headless `just` recipe for environments without a
display, such as CI or a cloud agent container.

## `M-x jotain-screenshot`

Captures the selected frame to `var/screenshots/<timestamp>.png`;
interactively, the path is echoed and pushed onto the kill ring. From
Lisp, the output file and format are parameters:

```elisp
(jotain-screenshot)                    ; var/screenshots/<timestamp>.png
(jotain-screenshot "/tmp/frame.svg" 'svg)
```

It needs a graphical frame on a cairo build (Jotain's Linux pgtk GUI
qualifies). It signals a `user-error` on tty frames and on builds
without `x-export-frames`: `noGui` (nix-on-droid) and the macOS NS port.

## The `emacs_screenshot` MCP tool

`init-ai.el` registers the command as a custom MCP tool with
[claude-code-ide][article-2], so a Claude Code session attached to
Emacs (`C-c q`) can call `emacs_screenshot`, get back the image path,
and read the file.

The tool needs `claude-code-ide-enable-mcp-server`, which Jotain sets
in the `claude-code-ide` block. It starts a small loopback-only MCP
server per Claude session, which also serves claude-code-ide's built-in
Emacs tools.

A typical exchange: ask Claude *"take a screenshot and check the
mode line"*; it calls `emacs_screenshot`, then views the returned PNG.

## Headless: `just screenshot`

With no display at all (CI, a cloud agent container, an SSH box), the
`screenshot` recipe builds Emacs via Nix, launches it with this repo's
config under a virtual X server (Xvfb, 1920×1080), captures the frame
once startup settles, and exits:

```bash
just screenshot                      # → var/screenshots/headless.png
just screenshot /tmp/frame.png       # explicit output path
```

`xvfb-run` comes from the devenv shell (Linux only: Xvfb is X11, and
the macOS port lacks `x-export-frames` anyway). The recipe exits 0 on
success, 2 if the capture failed, 1 if no image was written, and with
`timeout`'s status if the run wedged.

Caveats:

- **First run is slow.** It pays a full Nix build (a binary-cache pull
  of a multi-GB closure) plus a MELPA install of anything Nix doesn't
  provide, and needs network for both. The run is wrapped in
  `timeout 600`; raise it if a cold cache needs more.
- **Fonts may differ.** If fontconfig doesn't see the devenv-shell
  fonts, Xvfb falls back to whatever is available. The capture still
  succeeds, just less faithful to your desktop.
- `var/screenshots/` is under `var/`, so it is gitignored and wiped by
  `just clean-all`.

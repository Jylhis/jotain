# Launching Emacs

<Note>
The devenv shell provides tooling only; there is no `emacs` binary in it.
The supported launch path is **`just run-built`**: build Emacs via Nix,
then launch it with this configuration.
</Note>

Jotain supports three launch patterns. They're complementary: pick the
one that fits the task.

## One-shot

A fresh `emacs` process every time. Loads the full Jotain config and
pays package-init cost on every launch.

```bash
just run-built            # build for this platform, then launch result/bin/emacs
just run-built-debug      # same, with --debug-init and debug-on-error
just run-built-debug-log  # full debugging, logs mirrored into var/debug/<timestamp>/
just run-built-fast       # rebuild, then launch the AOT-compiled config (fastest start)
```

`just run-built` auto-detects the platform, builds the full
distribution (`just build`; on aarch64-linux the terminal-only
distribution via `just build-nox-full`), and launches
`./result/bin/emacs --init-directory=<repo>`, so it never touches
`~/.emacs.d`. The first run pays a `nix build` (usually a binary-cache
pull).

Best for sanity checks and trying out config changes; the startup cost
adds up for day-to-day editing.

## Daemon + client

Start Emacs once as a server and reuse it via lightweight clients. The
first frame is slow; every frame after is instant.

### In the repo (development)

Use the Nix-built binary:

```bash
just build          # or let a previous `just run-built` leave ./result behind
./result/bin/emacs --fg-daemon --init-directory="$PWD"   # foreground daemon
./result/bin/emacsclient -c                              # graphical client frame
./result/bin/emacsclient -t                              # terminal client frame
```

The daemon blocks; run it in another terminal (or under `tmux`) and
connect with `emacsclient` from elsewhere. Stop it with `C-c` in its
terminal, or from any client:

```bash
./result/bin/emacsclient -e '(kill-emacs)'
```

### As an installed user (home-manager)

The `services.jotain` module ships:

- A systemd user service (Linux) or launchd agent (macOS) that runs
  `emacs --fg-daemon`. `services.jotain.startWithUserSession` controls
  whether it starts with the session.
- `jotain-editor`: `emacsclient --tty`, falling back to `emacs -nw`
  when no daemon is running. Set as `$EDITOR` when
  `services.jotain.defaultEditor = true`.
- `jotain-visual`: `emacsclient --create-frame`. Set as `$VISUAL` by
  the same option.
- `jotctl {start|stop|status|restart|logs}` to manage the daemon (see
  below).
- A `.desktop` entry (`jotain-client.desktop`) for a GUI client,
  enabled by `services.jotain.client.enable`.

See *Module Options* in the appendix for the full option reference.

### Shell aliases

Inspired by [Rahul Juliato's launching-emacs-terminal post][article-1],
the module can install short aliases for the daemon and clients:

```nix
services.jotain = {
  enable = true;
  shellAliases.enable = true;
  # shellAliases.prefix = "j";   # for "jemd"/"jem"/"jemg"
};
```

| Alias | Expands to                              |
| ----- | --------------------------------------- |
| `emd` | `emacs --fg-daemon` (wrapped)           |
| `em`  | `jotain-editor` (`emacsclient --tty`)   |
| `emg` | `jotain-visual` (`emacsclient -c`)      |

They are added to the bash, zsh, and fish `shellAliases` that
home-manager manages.

### Managing the daemon (`jotctl`)

`emd` starts a *foreground* daemon. The supervised daemon (the launchd
agent on macOS, the `jotain` systemd user service on Linux) is managed
with `jotctl`, which is always on `PATH` when the module is enabled,
whatever `shellAliases.enable` says:

| Command          | macOS (launchd)                  | Linux (systemd --user)            |
| ---------------- | -------------------------------- | --------------------------------- |
| `jotctl status`  | `launchctl print …` (default)    | `systemctl --user status jotain`  |
| `jotctl start`   | `launchctl bootstrap` / kickstart | `systemctl --user start jotain`   |
| `jotctl stop`    | `launchctl bootout`              | `systemctl --user stop jotain`    |
| `jotctl restart` | `launchctl kickstart -k`         | `systemctl --user restart jotain` |
| `jotctl logs`    | launchd state + note¹            | `journalctl --user -u jotain -f`  |

¹ The launchd agent sets no `StandardOutPath`, so macOS doesn't capture
the daemon's stdout; `jotctl logs` prints the launchd state instead.

## Quick edit (`-Q -nw`)

For a stripped-down Emacs (editing `/etc/hosts` over SSH, a typo in a
200 MB log file, a demo without custom bindings), bypass Jotain with any
`emacs` on the host or the Nix-built one:

```bash
./result/bin/emacs -Q -nw --eval "(load-theme 'wombat t)"
```

This is the pattern [Rahul Juliato describes in basic-emacs-alias][article-2].
`-Q` skips `early-init.el`, `init.el`, site-lisp, and `~/.emacs.d/`;
`-nw` stays in the current terminal; wombat keeps it readable on dark
terminals. As a shell alias:

```bash
alias eq='emacs -Q -nw --eval "(load-theme '\''wombat t)"'
```

## Which one to use

| Situation                               | Use                  |
| --------------------------------------- | -------------------- |
| First-time setup, sanity checks         | `just run-built`     |
| Day-to-day editing, fast frame opens    | daemon + `em`/`emg`  |
| Sysadmin SSH session, ad-hoc edit       | `emacs -Q -nw` alias |
| Debugging a config regression           | `just run-built-debug` |

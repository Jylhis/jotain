Compilation mode runs a shell command, captures the output, and parses error messages so you can jump
to the source location. It works for compilers, linters, test runners, and anything else that prints
file/line references.


## Configuration

The compile package is configured in `lisp/init-prog.el`:

```elisp
(use-package compile
  :ensure nil
  :custom
  (compilation-scroll-output 'first-error)
  (compilation-ask-about-save nil)
  (compilation-always-kill t))
```

- `compilation-scroll-output` is `'first-error`: the buffer follows output and stops at the first
  error.
- `compilation-ask-about-save` is off: modified buffers are saved before compiling without a prompt.
- `compilation-always-kill` is on: a new compilation kills a running one without asking.


## Running a compilation

`M-x compile` prompts for a shell command and runs it. `M-x recompile` (or `g` in the compilation
buffer) re-runs the last command.

For per-language commands, `compile-multi` in `lisp/init-project.el` has presets for Go (test,
build, run, vet, golangci-lint, `go mod`), Python (pytest), Haskell (stack/cabal), OCaml (dune),
Meson, Nix (`nix flake check`, `nix fmt`, devenv), Rust (cargo), Zig, TypeScript/JavaScript (npm),
and C/C++ (CMake, CTest). Run `M-x compile-multi` to pick one; `consult-compile-multi` provides the
narrowing UI.


## Navigating errors

### In the compilation buffer

| Key   | Command                        | What it does                               |
|-------|--------------------------------|--------------------------------------------|
| `g`   | `recompile`                    | Re-run the last compilation command        |
| `M-n` | `compilation-next-error`       | Move to the next error message             |
| `M-p` | `compilation-previous-error`   | Move to the previous error message         |
| `RET` | `compile-goto-error`           | Jump to the source location at point       |
| `C-c C-f` | `next-error-follow-minor-mode` | Auto-display source as you move through errors |

### From any buffer

`M-g n` (`next-error`) and `M-g p` (`previous-error`) work from any buffer: Emacs tracks the last
buffer that produced errors and jumps there. This covers `compile`, `grep`, `occur`, and any other
mode with error-like output. `M-g M-n` and `M-g M-p` do the same while you keep holding Meta.

`M-g e` runs `consult-compile-error` (`lisp/init-completion.el`), a searchable list of all
compilation errors.

### Flymake integration

For in-buffer diagnostics, `M-n` and `M-p` are bound to `flymake-goto-next-error` and
`flymake-goto-prev-error` in `flymake-mode-map` (`lisp/init-prog.el`), so no compilation buffer is
needed.


## Editing grep results

`wgrep` (configured in `lisp/init-prog.el`) makes grep result buffers editable:

1. `consult-ripgrep`: search across the project
2. `C-c C-o` (`embark-export`): export results to a grep buffer
3. `C-x C-q`: enter `wgrep` edit mode
4. Edit the results as you would any buffer
5. `C-c C-c`: apply changes to all matched files

Emacs 31 also has a built-in `grep-edit-mode`.


## How error parsing works

Compilation mode parses output with `compilation-error-regexp-alist` and
`compilation-error-regexp-alist-alist`. Emacs ships entries for GCC, Java, Ruby, Python, Perl, and
many more, so common tools need no configuration.

Each entry has the shape:

```
(SYMBOL REGEXP FILE LINE COLUMN TYPE HYPERLINK HIGHLIGHT...)
```

`TYPE` controls severity: 2 = error, 1 = warning, 0 = info. It can also be a cons cell for
severity that depends on match groups.

### Adding a custom error regexp

For a tool whose output format isn't recognized:

```elisp
(with-eval-after-load 'compile
  (push '(my-linter
          "^\\[\\(?:ERROR\\|\\(WARN\\)\\)\\] \\([^:]+\\):\\([0-9]+\\):\\([0-9]+\\)"
          2 3 4 (1))
        compilation-error-regexp-alist-alist)
  (push 'my-linter compilation-error-regexp-alist))
```


## Useful variables

A few more compilation variables worth knowing:

```elisp
;; Skip warnings and info when navigating with next-error.
;; 2 = only errors, 1 = errors + warnings, 0 = everything.
(setopt compilation-skip-threshold 2)

;; Some languages (e.g. OCaml) use 0-indexed columns.
(setq compilation-first-column 0)

;; Auto-close the compilation window on success.
(add-hook 'compilation-finish-functions
          (lambda (buf status)
            (when (string-match-p "finished" status)
              (run-at-time 1 nil #'delete-windows-on buf))))
```


## The compilation mode family

Compilation mode is the infrastructure for any structured output with source locations:

- **grep-mode**: `M-x grep`, `M-x rgrep`, and `M-x lgrep` produce compilation-derived buffers with
  the same navigation.
- **occur-mode**: `M-x occur` participates in the same `next-error` infrastructure.
- **flymake**: uses compilation-style error navigation under the hood.

Whether you are looking at compiler errors, grep results, test failures, or linter output, the
workflow is the same: `M-g n` jumps to the next problem.

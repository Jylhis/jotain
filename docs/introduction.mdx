# Jotain

**Jotain** is a custom GNU Emacs configuration built from scratch. The name is Finnish for "something."

The project includes:

- A modular Emacs Lisp configuration, one file per concern (`lisp/init-*.el`)
- A Nix expression (`emacs.nix`) that builds GNU Emacs with its build flags exposed as arguments; default builds match the prebuilt [`nix-community/emacs-overlay`](https://github.com/nix-community/emacs-overlay) and nixpkgs attrs, so they are binary-cache hits
- A distribution (`nix/mk-overlay.nix`, exposed via `flake.nix` and the `default.nix` flake-compat shim) that ships Emacs with its packages, all ~275 tree-sitter grammars from nixpkgs, and the Info manual
- A development shell (`devenv.nix`) with linters, language servers, and docs tooling (Emacs is not in the shell; launch it with `just run-built`)
- A Home Manager service (`module.nix`) that runs Jotain as a user daemon with `emacsclient`
- A `Justfile` covering check, build, launch, pins, and cleanup

## Why Jotain?

Jotain doesn't sit on a framework like Doom or Spacemacs. Instead it has:

- **Nix-based builds**: reproducible Emacs with control over compile options, and binary-cache parity for the default configuration.
- **Modular Elisp**: one file per concern (`init-ui.el`, `init-completion.el`, `init-vc.el`, …). A package that only enhances a built-in (`dirvish` → `dired`, `magit` → `vc`) lives in the same file as that built-in; there is no "builtins.el" / "third-party.el" split.
- **Modern Emacs**: targets Emacs 31 (default build: emacs-overlay's newest release or pretest tag, currently 31.1; floor: Emacs 30.1), with native compilation, tree-sitter modes, lexical binding throughout, and the built-in `use-package`.
- **`setopt` by default**: user options (`defcustom`) are set via `setopt`, so `:set` callbacks and type validation run.

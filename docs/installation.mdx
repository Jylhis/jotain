# Installation

Jotain uses [Nix](https://nixos.org/) to build Emacs, driven by a `Justfile` task runner. Development happens in a [devenv](https://devenv.sh) shell: enter it with `devenv shell` (no `.envrc` is tracked; direnv users can create their own).

## Prerequisites

- [Nix package manager](https://nixos.org/download) with `nix-build` available
- [just](https://github.com/casey/just) task runner (not shipped by the devenv shell)
- [devenv](https://devenv.sh) (optional but recommended for development)

All `just` recipes assume the devenv shell is active. Without direnv, prefix any command with `devenv shell --`, e.g. `devenv shell -- just check`.

## Building Emacs

The default build targets the current system and includes every tree-sitter grammar from nixpkgs:

```bash
just build
```

This runs plain `nix-build`, which evaluates `default.nix` (a flake-compat wrapper around `flake.nix`) and builds `packages.<system>.default`: the full `jotainEmacsPackages` distribution (Emacs + use-package-scanned packages + tree-sitter grammars + the Info manual) assembled by `nix/mk-overlay.nix`. Its Emacs is the emacs-overlay `unstable` variant (the newest Emacs release or pretest tag, currently 31.1). The cache-parity invariant in `emacs.nix` makes its store path match emacs-overlay's prebuilt `emacs-unstable-pgtk` on Linux, so the base Emacs comes from `nix-community.cachix.org` instead of compiling.

### Build Matrix

Jotain ships four builds on {x86_64, aarch64} × {Linux, Darwin}: on Linux a pgtk/Wayland GUI and a terminal-only build; on Darwin a patched NS/Cocoa GUI (system-appearance, round-undecorated-frame, and fix-ns-x-colors, applied by default, so always built from source) and a terminal-only build. X11/Lucid/GTK3-x11/Motif/Athena and the macport fork are not supported; `emacs.nix` asserts them away.

```bash
just build           # full distribution: Emacs 31 (unstable) + every grammar (default)
just build-nox-full  # full terminal-only distribution (same attr the nix-on-droid module ships)
just build-bare      # bare Emacs from emacs.nix: the platform's matrix GUI
just build-nox       # --without-x --without-ns (terminal only, bare)
just build-git       # bleeding-edge master from git.savannah.gnu.org
just build-igc       # feature/igc3 MPS incremental GC branch
just build-igc-ccache # igc via ccacheStdenv (for from-source platforms; see emacs.nix)
just build-perf      # CPU-tuned perf build: -O3 -march/-mtune (opt-in; off every binary cache)
just build-android   # bare aarch64-linux nox, kept for cache-parity testing
```

Or call `nix-build` directly. `default.nix` exposes the flake packages, and bare-Emacs builds target `emacs.nix` with any argument the file accepts:

```bash
nix-build                                                # full distribution
nix-build -A emacs                                       # bare Emacs only
nix-build emacs.nix  --arg withNativeCompilation false   # no native-comp
nix-build emacs.nix  --arg variant '"git"'               # master
nix-build emacs.nix  --arg variant '"igc"'               # MPS GC branch
```

<Note>
`git`/`unstable`/`igc` build the revision pinned by emacs-overlay and are binary-cache hits on Linux and for the terminal-only Darwin build. The Darwin GUI is patched by default and always compiles from source. When pinning a custom commit via `--argstr rev "..."`, the first build fails and reports the hash to pass back via `--argstr hash "sha256-..."`.
</Note>

## Installing from a Consumer Flake

Jotain exposes Home Manager, NixOS, and nix-darwin modules. By default they install the full distribution (`jotainEmacsPackages`):

```nix
{
  imports = [ inputs.jotain.homeManagerModules.default ];

  services.jotain.enable = true;
}
```

`services.jotain.package` swaps in another Jotain-shaped distribution, for example the terminal-only build:

```nix
{
  imports = [ inputs.jotain.homeManagerModules.default ];

  services.jotain = {
    enable = true;
    package = inputs.jotain.packages.${system}.emacs-nox;
  };
}
```

### nix-on-droid (Android)

Jotain also ships a [nix-on-droid](https://github.com/nix-community/nix-on-droid) module for Emacs on Android (Termux/proot). Android is headless under proot, so the module installs a **terminal-only** Emacs into `environment.packages` and points `EDITOR`/`VISUAL` at an `emacsclient` wrapper. There is no systemd daemon, launchd agent, or GUI.

```nix
{
  imports = [ jotain.nixOnDroidModules.default ];

  services.jotain.enable = true;
}
```

Switch it in with `nix-on-droid switch --flake .#default`. `nixOnDroidConfigurations.default` in Jotain's `flake.nix` is a complete example.

<Note>
Like the NixOS / nix-darwin module (`module-system.nix`), this module installs the **Jotain Emacs package** (its Emacs packages, tree-sitter grammars, themes, and Info manual are on the `load-path`) but not Jotain's own `early-init.el` / `init.el` / `lisp/`. To boot the full configuration, point Emacs at a checkout with `--init-directory` (as `just run-built` does), or layer the Home Manager module through nix-on-droid's `home-manager.config`, which installs the config into `~/.config/emacs`. An `--init-directory` inside the read-only Nix store won't work, because Jotain writes `var/`, `elpa/`, and `eln-cache/` under `user-emacs-directory`.
</Note>

### Overriding nixpkgs

Downstream flakes may pin a different nixpkgs (release branches **24.05+** through unstable) by following the input:

```nix
inputs.jotain.inputs.nixpkgs.follows = "nixpkgs";
```

`emacs.nix` only forwards the build flags the base `make-emacs.nix` defines, so the modules still evaluate and build on older releases. On 24.05, `pkgs.emacs` is Emacs 29 while Jotain's Elisp targets Emacs 30/31: the build succeeds, but runtime behaviour is only guaranteed on the pinned unstable.

## Running

Jotain is launched from its own checkout via `--init-directory`, so it never touches `~/.emacs.d`.

```bash
just run-built          # build for this platform, then launch result/bin/emacs
just run-built-debug    # same, with --debug-init and debug-on-error
```

The devenv shell has no Emacs. See [Launching Emacs](/usage/launching) for the daemon + client pattern.

# Installation

This configuration uses [Nix](https://nixos.org/) to build Emacs, driven by a `justfile` task runner. It lives in the jylhis tree at `projects/distros/emacs`; there is no flake. Development happens in the jylhis lane shell: the tracked `.envrc` enters it through [direnv](https://direnv.net) (`direnv allow`).

## Prerequisites

- [Nix package manager](https://nixos.org/download) with `nix-build` available
- [just](https://github.com/casey/just) task runner
- [direnv](https://direnv.net) (optional but recommended for development)

All `just` recipes assume the lane shell is active (`direnv allow`).

## Building Emacs

The default build targets the current system and includes every tree-sitter grammar from nixpkgs:

```bash
just build
```

This runs plain `nix-build`, which evaluates `default.nix` (a shim over the tree's `nix/inputs.nix`) and builds `emacs-config.packages.<system>.default`: the full `emacsConfigPackages` distribution (Emacs + use-package-scanned packages + tree-sitter grammars + the Info manual) assembled by `nix/mk-overlay.nix`. Its Emacs is the emacs-overlay `unstable` variant (the newest Emacs release or pretest tag, currently 31.1). The cache-parity invariant in `emacs.nix` makes its store path match emacs-overlay's prebuilt `emacs-unstable-pgtk` on Linux, so the base Emacs comes from `nix-community.cachix.org` instead of compiling.

### Build Matrix

This configuration ships two builds on {x86_64, aarch64} Linux: a pgtk/Wayland GUI and a terminal-only build. X11/Lucid/GTK3-x11/Motif/Athena and the macport fork are not supported; `emacs.nix` asserts them away.

```bash
just build           # full distribution: Emacs 31 (unstable) + every grammar
```

The other builds have no recipe. Bare-Emacs builds target `emacs.nix` with any argument the file accepts:

```bash
nix-build                                                # full distribution (same as just build)
nix-build emacs.nix                                      # bare Emacs: the pgtk GUI
nix-build emacs.nix  --arg noGui true                    # terminal only, bare
nix-build emacs.nix  --arg withNativeCompilation false   # no native-comp
nix-build emacs.nix  --arg variant '"git"'               # master
nix-build emacs.nix  --arg variant '"igc"'               # MPS GC branch
```

<Note>
`git`/`unstable`/`igc` build the revision pinned by emacs-overlay and are binary-cache hits on Linux. When pinning a custom commit via `--argstr rev "..."`, the first build fails and reports the hash to pass back via `--argstr hash "sha256-..."`.
</Note>

## Installing the modules

The tree's `nix/inputs.nix` builds a flake-shaped `emacs-config` attrset with Home Manager and NixOS modules. The jylhis hosts get both through `outputs.nix`; anything else imports them from a checkout. By default they install the full distribution (`emacsConfigPackages`):

```nix
let
  emacs-config = (import /path/to/jylhis/nix/inputs.nix { }).emacs-config;
in
{
  imports = [ emacs-config.homeManagerModules.default ];

  services.emacsConfig.enable = true;
}
```

`services.emacsConfig.package` swaps in another configuration-shaped distribution, for example the terminal-only build:

```nix
{
  services.emacsConfig = {
    enable = true;
    package = emacs-config.packages.${system}.emacs-nox;
  };
}
```

### nix-on-droid (Android)

`module-nix-on-droid.nix` is a [nix-on-droid](https://github.com/nix-community/nix-on-droid) module for Emacs on Android (Termux/proot). Android is headless under proot, so the module installs a **terminal-only** Emacs into `environment.packages` and points `EDITOR`/`VISUAL` at an `emacsclient` wrapper. It is not part of the `emacs-config` attrset: import the file by path.

```nix
{
  imports = [ /path/to/jylhis/etc/emacs/module-nix-on-droid.nix ];

  services.emacsConfig.enable = true;
}
```

<Note>
Like the NixOS module (`module-system.nix`), this module installs the **configured Emacs package** (its Emacs packages, tree-sitter grammars, themes, and Info manual are on the `load-path`) but not the configuration's own `early-init.el` / `init.el` / `lisp/`. To boot the full configuration, point Emacs at a checkout with `--init-directory`.
</Note>

### Older nixpkgs

The modules take whatever `pkgs` the importing configuration has (release branches **24.05+** through unstable).

`emacs.nix` only forwards the build flags the base `make-emacs.nix` defines, so the modules still evaluate and build on older releases. On 24.05, `pkgs.emacs` is Emacs 29 while the configuration's Elisp needs Emacs 31.1: the build succeeds, but runtime behaviour is only guaranteed on the pinned unstable.

## Running

This configuration is launched from its own checkout via `--init-directory`, so it never touches `~/.emacs.d`.

```bash
just run-built               # build, then launch result/bin/emacs
just run-built --debug-init  # arguments are passed on to Emacs
```

The lane shell has no Emacs. See [Launching Emacs](/usage/launching) for the daemon + client pattern.

# Installation

Jotain is a [Nix](https://nixos.org/) flake. It builds GNU Emacs 31 with its packages, the tree-sitter grammars and the Info manual. The flake also provides a Home Manager module and a NixOS module.

The supported platform is `x86_64-linux`.

## Prerequisites

- [Nix](https://nixos.org/download) with the `nix-command` and `flakes` features enabled
- A Linux machine. The GUI build is pgtk.
- [just](https://github.com/casey/just) for the repository recipes (the development shell provides it)

The flake sets `extra-substituters` for `nix-community.cachix.org` and `jylhis.cachix.org`. Nix asks you to accept them on the first run, or use `--accept-flake-config`. Without them the build compiles Emacs from source.

## Try it

Run the full distribution without installing it:

```bash
nix run github:Jylhis/jotain
```

This starts the wrapped `emacs` with the bundled packages, grammars and Info manual. It does not load the configuration from the Nix store: Jotain reads `early-init.el`, `init.el` and `lisp/` from a checkout and writes `var/`, `elpa/` and `eln-cache/` there. To run the configuration, clone the repository and use `just run-built` (see below).

Other outputs:

```bash
nix build github:Jylhis/jotain#info    # the Info manual
nix build github:Jylhis/jotain#emacs   # bare Emacs without the packages
```

## Install with Home Manager

Add the flake as an input and import the module. The module runs Emacs as a user daemon with an `emacsclient` desktop entry:

```nix
# flake.nix
{
  inputs.jotain.url = "github:Jylhis/jotain";
  inputs.jotain.inputs.nixpkgs.follows = "nixpkgs";
}
```

```nix
# home.nix
{ inputs, ... }:
{
  imports = [ inputs.jotain.homeManagerModules.default ];

  services.jotain.enable = true;
}
```

The module applies its own overlay, so it does not need yours. `services.jotain.package` swaps in another Jotain-shaped distribution. The daemon runs under systemd.

## Install with NixOS

The NixOS module puts the distribution into `environment.systemPackages`:

```nix
{ inputs, ... }:
{
  imports = [ inputs.jotain.nixosModules.default ];

  services.jotain.enable = true;
}
```

`services.jotain.users.<user>` builds the programs of one user and installs them in that user's profile. The Home Manager module of the same user then takes the programs from there.

`services.jotain.spell.dictionaries` selects the dictionaries the bundled spell checker offers.

<Note>
The NixOS module installs the Jotain Emacs package (packages, grammars, themes, Info manual), not `early-init.el`, `init.el` or `lisp/`. To boot the full configuration, point Emacs at a checkout with `--init-directory`, as `just run-built` does, or use the Home Manager module, which installs the config into `~/.config/emacs`. An init directory inside the read-only Nix store does not work, because Jotain writes `var/`, `elpa/` and `eln-cache/` under `user-emacs-directory`.
</Note>

## Older nixpkgs

Downstream flakes may follow a different nixpkgs (release branches **24.05+** through unstable):

```nix
inputs.jotain.inputs.nixpkgs.follows = "nixpkgs";
```

`emacs.nix` only forwards the build flags the base `make-emacs.nix` defines, so the modules still evaluate and build on older releases. On 24.05, `pkgs.emacs` is Emacs 29 while Jotain's Elisp needs Emacs 31.1: the build succeeds, but runtime behaviour is only guaranteed on the pinned unstable.

## Developing in a checkout

Clone the repository and enter the development shell:

```bash
git clone https://github.com/Jylhis/jotain.git
cd jotain
nix develop        # or nix-shell
```

The shell has `just`, `treefmt`, the Nix linters, the language servers the configuration shells out to, the docs tooling and the fonts. It has no Emacs. The recipes assume it is active.

```bash
just build           # nix-build: the full distribution
just run-built       # build, then launch result/bin/emacs with this checkout as the init directory
just run-built-debug # same, with --debug-init and debug-on-error
```

## Building Emacs

The default build targets `x86_64-linux` and includes every tree-sitter grammar from nixpkgs. `just build` runs plain `nix-build`, which evaluates `default.nix` (a flake-compat wrapper around `flake.nix`) and builds `packages.<system>.default`: the full `jotainEmacsPackages` distribution (Emacs + use-package-scanned packages + tree-sitter grammars + the Info manual) assembled by `nix/mk-overlay.nix`. Its Emacs is the emacs-overlay `unstable` variant (the newest Emacs release or pretest tag, currently 31.1). The cache-parity invariant in `emacs.nix` makes its store path match emacs-overlay's prebuilt `emacs-unstable-pgtk`, so the base Emacs comes from `nix-community.cachix.org` instead of compiling.

### Build matrix

Jotain ships one build: a pgtk/Wayland GUI on `x86_64-linux`. X11/Lucid/GTK3-x11/Motif/Athena are not supported; `emacs.nix` asserts them away.

```bash
just build            # full distribution: Emacs 31 (unstable) + every grammar (default)
just build-bare       # bare Emacs from emacs.nix: the pgtk GUI
just build-git        # bleeding-edge master from git.savannah.gnu.org
just build-igc        # feature/igc3 MPS incremental GC branch
just build-igc-ccache # igc via ccacheStdenv (see emacs.nix)
just build-perf       # CPU-tuned perf build: -O3 -march/-mtune (opt-in; off every binary cache)
```

Or call `nix-build` directly. `default.nix` exposes the flake packages, and bare-Emacs builds target `emacs.nix` with any argument the file accepts:

```bash
nix-build                                                # full distribution
nix-build -A emacs                                       # bare Emacs only
nix-build emacs.nix  --arg withNativeCompilation false   # no native-comp
nix-build emacs.nix  --arg variant '"git"'               # master
nix-build emacs.nix  --arg variant '"igc"'               # MPS GC branch
```

<Note>
`git`/`unstable`/`igc` build the revision pinned by emacs-overlay and are binary-cache hits. When pinning a custom commit via `--argstr rev "..."`, the first build fails and reports the hash to pass back via `--argstr hash "sha256-..."`.
</Note>

## Running

Jotain is launched from its own checkout via `--init-directory`, so it never touches `~/.emacs.d`. See [Launching Emacs](/usage/launching) for the daemon + client pattern.

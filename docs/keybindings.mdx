Jotain follows Emacs conventions: only **global** rebindings live in
[`lisp/init-keys.el`](https://github.com/Jylhis/jotain/blob/main/lisp/init-keys.el);
per-package bindings stay colocated with the package's `use-package` block.
The built-in `which-key` is enabled, so after any prefix key a menu of
continuations appears in the echo area. The labels below are registered via
`which-key-add-key-based-replacements` in `init-keys.el`, so they show up in
those menus instead of bare command names.

## Mode-local overrides

Some modes add local bindings:

- `dired-mode`: `C-c C-e` → `wdired-change-to-wdired-mode` (writable dired)
- `sops-mode`: `C-c C-c` save, `C-c C-k` cancel, `C-c C-d` edit
- Minibuffer: `C-c C-o` → `embark-export`
- `dired`, `calc`, `Info`, `ibuffer`: `C-o` opens the `casual` menu
  for the mode (`<f2>` during isearch)
- `org-mode`: `C-c b` is an Org Babel notebook prefix (`b` run buffer,
  `e` run subtree, `r` restart session and run buffer, `s` switch to
  session, `k` clear results, `t` tangle). Single blocks stay on
  `C-c C-c`, and Org's own `C-c C-v` babel map is untouched. See
  [Notebooks with Org Babel](/usage/notebooks).
- `org-mode`: `C-c C-r` is the `verb` HTTP client map.

## Embark action menu

`C-.` (`embark-act`) opens a keyboard-driven "right-click" menu of
actions for the thing at point: a minibuffer candidate, file name,
buffer, URL, Elisp symbol, or the active region. `C-;` (`embark-dwim`)
runs the default action directly. These keys are pressed *after* `C-.`:

| Key | Action |
| --- | --- |
| `C-h` | Searchable `completing-read` of every applicable action — the discovery entry point |
| `E` | `embark-export` — promote the candidate set to a buffer (grep for ripgrep/grep, occur for `consult-line`, dired for files, ibuffer for buffers) |
| `A` | `embark-act-all` — run one action on *every* current candidate |
| `B` | `embark-become` — re-run the input you typed through a different command |
| `i` | Insert the candidate into the buffer you came from |
| `w` | Copy the candidate to the kill-ring |

Two habits worth forming:

- **Search → edit.** `consult-ripgrep` → `C-. E` exports to a grep
  buffer; `C-x C-q` (`wgrep`) then makes it editable, so you can rewrite
  every match and save across all files at once.
- **Keep the session alive.** Acting on a candidate exits the
  minibuffer; with a prefix (`C-u C-.`) it stays open for further
  actions, e.g. deleting or renaming several files in a row.

Embark resolves candidate paths through `project.el`, so the file
actions (`w` copy path, `r` rename, `d` delete, `j` jump to dired) work
directly on `project-find-file` candidates. `embark-become`'s file map
offers `p` for `project-find-file`, so `C-. B p` re-runs a plain
`C-x C-f` input through the project finder.

## Window navigation

Shift + arrow keys move between windows (`windmove-default-keybindings`).
`M-o` cycles through windows; `C-x j` toggles a two-window layout between
horizontal and vertical splits.

## Why no leader-key framework?

["general.el to conquer Emacs keybindings"](https://bicycleforyourmind.com/generaldotel-to-conquer-emacs-keybindings)
argues for [`general.el`](https://github.com/noctuid/general.el) as a
unified keybinding layer. Jotain doesn't adopt it: its main
differentiator is `:states` for evil-mode, which Jotain doesn't use, and
the built-in `keymap-set`, `which-key`, and use-package `:bind` already
cover discoverability and leader-key ergonomics. The article's idea of
memorable, self-documenting prefixes lives in the
`which-key-add-key-based-replacements` table in `init-keys.el`.

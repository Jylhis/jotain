#+DESCRIPTION: How Jotain configures compilation mode, per-language compile commands, error navigation and editing of grep results.

* Compilation and grep
:PROPERTIES:
:CUSTOM_ID: compilation
:END:

Compilation mode runs a command, captures its output and links error messages to source locations. The mechanics are in [[info:emacs#Compilation]] and [[info:emacs#Compilation Mode]], and grep buffers use the same machinery ([[info:emacs#Grep Searching]]). This chapter covers what Jotain sets up.

** Compilation setup
:PROPERTIES:
:CUSTOM_ID: compilation-config
:END:

=init-prog.el= sets =compilation-ask-about-save= to nil, so modified buffers are saved before compiling without a prompt, and =compilation-always-kill= to t, so a new compilation replaces a running one.

=compile-multi= (in =init-project.el=) offers named compile commands per major mode. Presets exist for Go, Python (pytest), Haskell, OCaml (dune), Meson, Nix (=nix flake check=, =nix fmt=, devenv), Rust (cargo), Zig, JavaScript and TypeScript (npm) and C/C++ (CMake, CTest). =M-x compile= prompts for a shell command and runs it, and =M-x recompile= (or =g= in the compilation buffer) re-runs the last one. =M-x compile-multi= picks a named command, =consult-compile-multi= provides narrowing, and the Embark integration adds actions to them. It complements =projection= on =C-x P=, which detects commands from project files.

** Navigating errors
:PROPERTIES:
:CUSTOM_ID: compilation-nav
:END:

=M-g n= and =M-g p= (=next-error=, =previous-error=) work from any buffer and cover compilation, grep and occur. =M-g e= runs =consult-compile-error=, a searchable list of all errors. =M-g M-n= and =M-g M-p= do the same while you keep holding Meta. In the compilation buffer, =M-n= and =M-p= move between error messages, =RET= jumps to the source location at point and =C-c C-f= toggles =next-error-follow-minor-mode=, which shows the source as you move. In buffers with Flymake, =M-n= and =M-p= go to the next and previous diagnostic, with no compilation buffer needed.

** Editing grep results
:PROPERTIES:
:CUSTOM_ID: compilation-wgrep
:END:

=wgrep= makes grep buffers editable and saves the changed files (=wgrep-auto-save-buffer=). The workflow across a project:

1. Run =consult-ripgrep=.
2. Press =C-c C-o= (or =C-. E=) to export the matches to a grep buffer.
3. Press =C-x C-q= to start editing, change the matches, and press =C-c C-c= to apply them to every file.

Emacs 31 also has a built-in =grep-edit-mode=.

** Error parsing
:PROPERTIES:
:CUSTOM_ID: compilation-parsing
:END:

Compilation mode parses output with =compilation-error-regexp-alist= and =compilation-error-regexp-alist-alist=. Emacs ships entries for GCC, Java, Ruby, Python, Perl and many more, so common tools need no configuration. An entry has the shape =(SYMBOL REGEXP FILE LINE COLUMN TYPE HYPERLINK HIGHLIGHT...)=, where =TYPE= is 2 for an error, 1 for a warning and 0 for info. For a tool whose output is not recognised, add an entry:

#+begin_src emacs-lisp
(with-eval-after-load 'compile
  (push '(my-linter
          "^\\[\\(?:ERROR\\|\\(WARN\\)\\)\\] \\([^:]+\\):\\([0-9]+\\):\\([0-9]+\\)"
          2 3 4 (1))
        compilation-error-regexp-alist-alist)
  (push 'my-linter compilation-error-regexp-alist))
#+end_src

Two more variables are worth knowing: =compilation-skip-threshold= (2 skips warnings and info when navigating with =next-error=) and =compilation-first-column= (0 for tools with 0-indexed columns, as OCaml has). =grep=, =rgrep=, =lgrep= and =occur= buffers use the same navigation, so =M-g n= jumps to the next problem whatever produced it.

# Packages

Jotain is a "use-package + Nix" configuration: Nix puts the packages on `load-path`, so `use-package` finds them without touching the network. A package Nix doesn't provide falls through to MELPA at install time.

## Provenance

- **Built-in to Emacs 30+**: opt out of installation with `:ensure nil`.
- **From the package archives, via Nix**: every other `use-package` block. The distribution (`nix/mk-overlay.nix`) scans the `use-package` declarations with `nix/use-package.nix` and maps them to the emacs-overlay package set. `use-package-always-ensure` is `t` (set in `early-init.el`), so these blocks need no `:ensure`; the package is already installed when Nix provides it.
- **Built by Nix**: packages that are on no archive (e.g. `claude-code-ide`, `combobulate`) are built in `nix/extra-packages.nix`, declared with `:ensure nil`, and added to the distribution through `nix/nix-provided-packages.nix`.
- **MELPA / NonGNU ELPA fallback**: when Nix doesn't provide a scanned package, `:ensure` installs it from the archives registered in `init.el`:

  ```elisp
  (add-to-list 'package-archives '("melpa"  . "https://melpa.org/packages/")     t)
  (add-to-list 'package-archives '("nongnu" . "https://elpa.nongnu.org/nongnu/") t)
  ```

## Tree-sitter grammars

The full distribution (`just build` and friends) ships *every* tree-sitter grammar in nixpkgs via `epkgs.treesit-grammars.with-all-grammars`. nixpkgs' `site-start.el` points `treesit-extra-load-path` at the bundle, so every built-in `*-ts-mode` finds its grammar out of the box.

## Packages that live in Nix

`nix/extra-packages.nix` builds these with `trivialBuild` from pinned revisions:

- **`jylhis-emacs-themes`**: the design-system themes; the revision comes from `nix/design-pin.nix`, the pin shared with the website's vendored CSS.
- **`claude-code-ide`**: from `manzaltu/claude-code-ide.el`, with `websocket` and `web-server` as dependencies (`transient` is built in to Emacs 30+).
- **`combobulate`**: from `mickeynp/combobulate`; its dependencies are Emacs built-ins.
- **`eglot-booster`**: wraps stdio language servers in `emacs-lsp-booster`.
- **`qml-ts-mode`**: tree-sitter QML mode.
- **`tagref`**: Emacs integration for the `tagref` cross-reference checker.

It also overrides a few archive packages:

- **`majutsu`** (Magit-style Jujutsu porcelain) and **`project-nix-store`** are pinned ahead of the versions in the package set.
- **`ghostel`** is temporarily rebuilt Elisp-only, because the upstream native-module build can't currently be fetched on CI; the module is downloaded at runtime instead.
- **`xref`**, **`project`**, **`eglot`**, and **`flymake`** are replaced with empty shims so stale GNU ELPA copies pulled in as dependencies can't shadow Emacs 31's in-tree versions.

## The devenv shell

The devenv shell provides **tooling only**: linters, language servers, the docs chain, fonts. Emacs is *not* in the shell; build and launch the editor with `just run-built`.

## Adding a new package

Usually a `use-package` block in the right `init-*.el` module is enough; `:ensure t` is implicit via `use-package-always-ensure`:

```elisp
(use-package some-package
  :mode "\\.ext\\'"
  :custom
  (some-package-option t)
  :config
  ;; configuration here
  )
```

If the package is on no archive, add it to `nix/extra-packages.nix` with `trivialBuild` (pinned GitHub revision), list it in `nix/nix-provided-packages.nix`, and declare it with `:ensure nil` in the module.

One invariant: `nix/use-package.nix` **scans** the Elisp with a regex; it does not evaluate it. Write `use-package` forms out literally (a macro that generates them is invisible to the scan), and don't nest them inside another form's `:config`. A form with `:disabled` is always dropped from the Nix-provided set, even if its value would be nil at runtime.

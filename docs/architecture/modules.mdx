# Modules

Jotain's Elisp configuration is split across `lisp/init-*.el`, one file per concern. A package that only exists to enhance a built-in lives in the same file as that built-in (`dirvish` with `dired`, `magit` with `vc`). There is no "builtins.el" / "third-party.el" split.

## Conventions

- Every module is `lisp/init-<concern>.el`, starts with a `lexical-binding: t` cookie, and ends with `(provide 'init-<concern>)`.
- Modules are loaded in order from `init.el`.
- `use-package-always-ensure` is `t` (set in `early-init.el`), so every `use-package` block installs its package if missing. Built-ins and Nix-provided packages opt out with `:ensure nil`; Nix puts the latter on `load-path`, so no network access is needed.
- User options (`defcustom` variables) are set with `setopt`, not `setq`, so their `:set` callbacks and `:type` validation run.

## Load order

## Core modules

### `init-core`

GC, encoding, and baseline defaults. Restores `gc-cons-threshold` to 16 MiB after the early-init bump and pauses GC while the minibuffer is open; forces UTF-8; enables `save-place-mode`, `recentf`, `savehist`, `repeat-mode`, `uniquify`, `ibuffer` as the buffer list, and `global-auto-revert-mode`. Defines `jotain-var-dir` and the `jotain-var-file` helper, which every module uses to keep state files (recentf, savehist, bookmarks, keyfreq, forge, …) under `var/`. On macOS, `Cmd` is Meta and `Option` is Super; right Option is left alone for special characters. `read-extended-command-predicate` hides `M-x` candidates tagged for other major modes; typing a full command name still runs it.

### `init-keys`

Global bindings only; per-package bindings live in their `use-package` block. Unbinds `C-z` / `C-x C-z`, binds `M-o` to `other-window`, enables `windmove-default-keybindings` (Shift + arrows), binds `jotain-toggle-window-split` to `C-x j`, and (on Emacs 31+) adds a repeat-map for the `window-layout-*` commands under `C-x W`. It also registers `which-key` labels for the shared `C-c` / `C-x` prefixes (`C-c n` org-roam, `C-c r` eglot-refactor, `C-c o` combobulate, `C-x P` project, …). See [Keybindings](/keybindings) and [Ergonomics](/ergonomics).

### `init-ui`

Appearance. Uses the Jylhis design system themes `jylhis-light` / `jylhis-dark` (customisable via `jotain-theme-light` / `jotain-theme-dark`), with `auto-dark-mode` following the system appearance. The themes come from the pin in `nix/design-pin.nix`; if they are unavailable or fail to load, the module falls back to `modus-operandi` / `modus-vivendi`. Installs `doom-modeline` and picks the first available font from `jotain-font-preferences` (BlexMono Nerd Font → JetBrains Mono Nerd Font → Iosevka Nerd Font → DejaVu Sans Mono). Also enables `display-line-numbers`, `pixel-scroll-mode`, `hl-line-mode`, `show-paren-mode`, the built-in `which-key`, `nerd-icons` for dirvish/ibuffer/corfu/marginalia, `hl-todo`, `breadcrumb`, `pulsar`, `rainbow-delimiters`, and `indent-bars`.

### `init-help`

Built-in help tweaks (`help-window-select`) plus `helpful` for richer `describe-*` buffers. See [Finding Information in Emacs](/finding-information-in-emacs).

### `init-docs`

Makes the bundled `jotain.info` manual discoverable from `C-h i` in a source checkout. Nix-installed distributions don't need it: their wrapper already sets `INFOPATH`. The module adds the first existing directory among `JOTAIN_INFO_DIR`, `result-info/share/info` (from `just info`), and `result/share/info` to `Info-additional-directory-list`; `C-h i d m Jotain RET` then opens the manual.

### `init-editing`

Editing primitives: `electric-pair-mode`, `delete-selection-mode`, `whitespace-mode`, undo settings, and region tools (`expreg`, `multiple-cursors`, `vundo`). Also `keyfreq`, which records command frequency to `var/` (`M-x keyfreq-show`), enabled at `after-init`.

### `init-completion`

The vertico stack in the minibuffer and corfu + cape in buffers, plus the built-in `minibuffer` tweaks they rely on. They share one file because changing one nearly always means changing the others. `C-s` stays `isearch-forward`; `M-s l` is `consult-line`.

### `init-navigation`

`dired` and its extensions, `dirvish`, and `winner-mode`. Directional window movement (`windmove`) is in `init-keys`; `project` is in `init-project`.

### `init-casual`

`casual` Transient menus over built-in tools, each bound in its own mode map: `C-o` in dired, calc, Info, and ibuffer, `<f2>` during isearch.

### `init-vc`

`vc` limited to Git + Jujutsu (other backends cost startup time), `vc-jj` for jj support in `vc` / `project.el`, `magit` with refined hunks and worktrees in `magit-status`, `majutsu` as a magit-style jj porcelain (`C-c j` log, `C-c M-j` dispatch), `magit-todos`, `forge` (built-in sqlite backend, `emacsql-sqlite-builtin`), `diff-hl` with `diff-hl-flydiff-mode`, and `ediff`. `smerge-mode` needs no config; it activates on conflicts with its stock `C-c ^` bindings. The `N/M` modeline counter is backend-aware: a `.jj` directory selects jj probes (`jj diff --git`, an `author_date` revset), otherwise git. For correct jj diff and conflict rendering, set `ui.diff-formatter = ":git"` and `ui.conflict-marker-style = "git"` via `jj config edit --user`.

### `init-prog`

The shared substrate for programming modes: `prog-mode` hooks, `treesit`, `eglot`, `flymake`, `eldoc`, `apheleia` (format-on-save), and `compile`. All LSP wiring lives here. Beyond the curated per-language hooks, `eglot` auto-starts for any project file whose language server is on the buffer's project `PATH`, so enabling a language in a project's devenv lights up its LSP with no extra config. When `rass` (rassumfrassum, shipped in the devenv shell) is on `PATH`, TypeScript/TSX buffers run `typescript-language-server` through it; `eslint-lsp` and `tailwindcss-language-server` join only when `jotain-prog-enable-risky-js-lsp` is non-nil, because they can execute project JavaScript config. Python buffers use the `rass python` preset (basedpyright + ruff) when both binaries are present. If a prerequisite is missing, eglot falls back to a single server, so projects using `pylsp` / `pyright` keep working. `M-x jotain-sonarlint` starts on-demand SonarLint analysis via `sonarlint-ls`; SonarCloud connected mode is configured per project via `eglot-workspace-configuration` in `.dir-locals.el`. Debugging uses `dape` (`C-x C-a` prefix); adapters such as `dlv` and `debugpy` come from the project or host `PATH`, like the LSP servers.

### `init-snippets`

Snippets via `tempel`, chosen over `skeleton`/`abbrev` and the heavier `yasnippet` because it shares an author with the corfu/cape/vertico stack and plugs into `completion-at-point-functions`: snippet names appear in the corfu popup. `M-+` (`tempel-complete`) and `M-*` (`tempel-insert`) expand them; `M-}` / `M-{` (or `C-M-n` / `C-M-p`) move between fields, and `TAB` is deliberately not a field key. Templates live in `templates/jotain.eld`, keyed by major mode, so adding one never touches Elisp. `eglot-tempel` lets Tempel expand the snippets language servers return (e.g. argument placeholders).

### `init-project`

`project` plus two complementary command systems: `projection` (`C-x P`, project types and commands auto-detected from Makefiles, justfiles, `Cargo.toml`, etc.) and `compile-multi` (named per-mode compile commands like "go test", "pytest file", "nix flake check"). Neither fully covers the other.

### `init-devenv`

Binds the in-repo [devenv.sh](https://devenv.sh) library `lisp/devenv.el` into the configuration. The library is a standalone package (own `devenv-` namespace, no `jotain-` dependencies) and the one file under `lisp/` that is not an `init-*` module. `C-c v` opens a transient with task and script runners, `devenv test` / `build` / `update` / `gc` in compilation-mode with Nix-trace error matching, a process dashboard over `devenv up` / `down`, introspection (`devenv eval` / `info` / `search`), and `devenv-reload`. `devenv.nix` buffers use the bundled `devenv lsp` server; other Nix files keep `nil`. `devenv-mcp-setup` registers the project's `devenv mcp` server with mcp.el for gptel. The library's native loader (`devenv-env-global-mode`) loads each trusted project's environment: it sources `devenv print-dev-env` in bash (so the shellHook runs) and applies the result buffer-locally. direnv/envrc is not used; Jotain sets `devenv-env-defer-to-direnv` to nil. See [devenv integration](/usage/devenv).

### `init-ai`

AI assistants. `claude-code-ide` on `C-c q` drives the Claude Code CLI. `eca` on `C-c e` is the Editor Code Assistant client (chat, completion, rewrite, MCP) talking to a Nix-provided server. `gptel` on `C-c s` (send) / `C-c S` (menu) has four backends: OpenRouter (default, `anthropic/claude-sonnet-4.6`), Anthropic, Gemini, and a local Ollama. `mcp` loads after `gptel` for Model Context Protocol tools. API keys come from the environment (`OPENROUTER_API_KEY` / `ANTHROPIC_API_KEY` / `GEMINI_API_KEY`) first, then `auth-source`. The eca server reads only its own environment, so `jotain-ai-export-api-keys` exports any missing key from auth-source before each eca session.

On the Home Manager side, `services.jotain.eca` generates the eca server config (`eca.openrouter.enable` adds the default provider from `config/eca/config.json`; `eca.settings` is a freeform merge; the legacy `services.jotain.openrouter.enable` is a renamed alias). Keys come from `services.jotain.environmentFile`, or via auth-source: `services.jotain.authSources` adds runtime authinfo files (sops/agenix) and `services.jotain.onePassword.enable` puts the `op` CLI on `PATH`. `services.jotain.claudeCode.enable` supplies the Claude Code CLI.

### `init-shell`

`eshell`, `comint`, and `ielm`, grouped because shells and REPLs share concerns (input handling, history, prompts). The PTY terminal emulator lives in `init-terminal`.

### `init-terminal`

Terminal support in both directions. Inside Emacs: `ghostel`, a terminal emulator built on libghostty-vt (Ghostty's VT engine) through a native module, with a real PTY, shell integration (OSC 7 directory tracking, OSC 133 prompt navigation), and OSC 52 clipboard. When the native module is missing, `ghostel-module-auto-install` downloads it into the package directory on first `M-x ghostel`; that directory must be writable (e.g. a MELPA install under `elpa/`). Emacs inside a terminal: `global-kkp-mode` (Kitty Keyboard Protocol), `clipetty` (OSC 52 clipboard through SSH and tmux), `xterm-mouse-mode`, and `tty-tip-mode` on Emacs 31+, all no-ops in GUI frames. Ghostel advertises `TERM=xterm-ghostty`, like Ghostty itself; the `xterm-ghostty → xterm-256color` alias lives in `early-init.el` because terminal initialisation runs before `init.el`.

### `init-systems`

Sysadmin tools: `sops` for encrypted files, `logview`, and `auth-source-1password` so `forge`, `gptel`, `smtpmail`, etc. resolve credentials from the 1Password vault.

### `init-writing`

Prose: `jinx` spell-checking, `markdown-mode`, `denote`, `pdf-tools`. Org has its own file.

### `init-org`

`org-mode`, `org-modern`, capture templates, agenda, and `org-roam`. Binds `C-c a` → `org-agenda`, `C-c c` → `org-capture`, `C-c l` → `org-store-link`.

It also makes an `.org` file usable as a notebook: `jotain-org-babel-languages` (a curated set backed by `ob-*` libraries Org itself ships), an `org-confirm-babel-evaluate` predicate that skips the prompt for files under `org-directory` or inside the current project, inline-image refresh after every run, source-block editing that preserves indentation, and a `C-c b` prefix in Org buffers (`b` run buffer, `e` run subtree, `r` restart session and run buffer, `s` switch to session, `k` clear results, `t` tangle). See [Notebooks with Org Babel](/usage/notebooks).

### `init-http`

`verb`, an Org-based HTTP client: requests are Org headings whose children inherit the parent's URL, headers, and body. Its command map is on `C-c C-r` in Org buffers.

## Language modules

Each `init-lang-*.el` file sets `:mode` regexes and language-specific tweaks for a group of related languages. Formatters (`apheleia`) and LSP hooks live in `init-prog.el`.

- **`init-lang-nix`**: `nix-ts-mode`, formatted with `nixfmt` via apheleia.
- **`init-lang-rust`**: `rust-ts-mode` (built-in) plus rust-analyzer workspace settings (clippy on save, build scripts, proc macros).
- **`init-lang-python`**: `python-ts-mode` (built-in) with `python3` as the interpreter, or IPython for the REPL when it is on `PATH`. The language server comes from the project environment (see `init-prog`).
- **`init-lang-go`**: `go-ts-mode` / `go-mod-ts-mode` / `go-work-ts-mode` (built-in), with a gopls workspace config that enables inlay hints, staticcheck, and the `unusedparams` / `shadow` / `nilness` / `unusedwrite` analyses. A `major-mode-remap-alist` entry sends the classic `go-mode` to `go-ts-mode`. `go-tag` (struct tags) and `gotest` (test, benchmark, and coverage runs) live under the mode-local `C-c C-t` prefix. Formatting uses `goimports`, debugging `dlv`. All Go tooling (`go`, `gopls`, `goimports`, `dlv`, `gomodifytags`) comes from the project or host `PATH`.
- **`init-lang-web`**: `typescript-ts-mode`, `tsx-ts-mode`, CSS, JSON, and related modes. Plain `.html` / `.htm` uses the built-in `mhtml-ts-mode`; `web-mode` handles templating dialects (`.php`, `.erb`, `.jsp`, `.tpl`, mustache, Django).
- **`init-lang-devops`**: Dockerfile, Terraform, gitlab-ci, justfile, Ansible, Robot Framework, Bazel/Starlark (`BUILD`, `WORKSPACE`, `MODULE.bazel`, `*.bzl`, `.bazelrc`, …), and the Structurizr and LikeC4 architecture DSLs. `jotain-docker-backend` (`'podman` by default, `'docker` for Docker) picks the runtime command used by `dockerfile-mode`. Bazel files are formatted with buildifier.
- **`init-lang-data`**: YAML, CSV (with `csv-align-mode`), SQL (`sql-indent`), Jinja2, gnuplot.
- **`init-lang-systems`**: C/C++ (`c-ts-mode` / `c++-ts-mode` via `jotain-prog-ts-remaps`; `clangd`, `clang-format`, `codelldb`), CUDA (`cuda-ts-mode`, defined here on the `cuda` grammar; `derived-mode-add-parents` makes it count as `c++-ts-mode`, so the C++ tools apply), CMake, Meson, Haskell (`haskell-ts-mode`, derived from `haskell-mode` so eglot's HLS entry matches), OCaml (`neocaml-mode` / `neocaml-interface-mode`, `tuareg` for `.mll` / `.mly`, `dune`; `ocamllsp`, `ocamlformat`), and Zig (`zig-ts-mode`, `zls`). `cc-mode` stays for its `auto-mode-alist` decisions and as the fallback without a grammar.
- **`init-lang-qml`**: `qml-ts-mode` for QML (Quickshell, Qt Quick); `qmlls` and `qmlformat` are wired in `init-prog`.

## Adding a new module

1. Create `lisp/init-<concern>.el` with the usual Elisp headers and a `lexical-binding: t` cookie.
2. End the file with `(provide 'init-<concern>)`.
3. Add a `(require 'init-<concern>)` line in `init.el` at the right point in the load order.
4. Run `just check`: `elisp-lint` checks the parens, and `elisp-compile` byte-compiles with warnings as errors.

# Architecture Overview

This configuration is organised into layers, each with one responsibility.

## File Structure

```
etc/emacs/
├── early-init.el       # Pre-package/GUI initialisation
├── init.el             # Entry point: loads modules in order
├── lisp/               # Modular Elisp config (init-*.el, one per concern)
├── emacs.nix           # Bare Emacs build (cache-parity invariant)
├── default.nix         # Entry point (shim over the tree's nix/inputs.nix)
├── overlay.nix         # Standalone nixpkgs overlay (wraps nix/mk-overlay.nix)
├── module.nix          # Home Manager module for the daemon
├── module-system.nix   # NixOS module
├── module-nix-on-droid.nix  # nix-on-droid module (terminal-only build)
├── nix/
│   ├── mk-overlay.nix         # Overlay implementation: distribution assembly
│   ├── checks.nix             # Checks (lint, compile, tests, builds)
│   ├── use-package.nix        # use-package scanner (Elisp → epkgs mapping)
│   └── ...                    # docs, site, extra packages, treefmt helpers
├── devenv.nix          # Development shell (tooling only, no Emacs)
├── devenv.yaml         # devenv inputs
├── justfile            # Task runner recipes
├── docs/               # Documentation sources (rendered into the site,
│                       #   the Info manual, and the man page; docs.json
│                       #   defines page order)
├── test/               # ERT tests (every *.el here is loaded by elisp-test)
├── bench/              # Startup-benchmark wrapper init files
├── templates/          # Tempel snippet templates (default.eld)
├── config/             # Auxiliary tool config (e.g. eca)
├── etc/                # Debug harness, language-eval registry, elisp-doc engine
└── journal/            # Development journal entries
```

## Layers

### Emacs Lisp Layer

1. **`early-init.el`** runs before `package.el`, before the first frame, and before `init.el`. It handles what must happen that early: the startup GC threshold, `use-package-always-ensure`, frame chrome, the eln-cache redirect, and terminal aliases.

2. **`init.el`** is a tiny entry point. It registers MELPA/NonGNU ELPA as fallback archives, puts `lisp/` on the load-path, points `custom-file` at `var/custom.el` (write-only, never loaded back), and `require`s each module in order. Archives are never fetched at startup: only when `package-install` finds an empty cache, or on an explicit `M-x package-refresh-contents`.

3. **`lisp/init-*.el`**: one file per concern. See [Modules](/architecture/modules).

### Nix Layer

1. **`emacs.nix`** builds bare Emacs from emacs-overlay's `unstable` (default), `git`, or `igc` attrs, or nixpkgs' `emacs` (`mainline`, the cache-parity canary), with the build flags exposed as arguments. The matrix is pgtk GUI or terminal-only on Linux. Default builds produce the same store paths as the matching prebuilt attrs, so they are cache hits on Hydra and `nix-community.cachix.org`; custom `rev` pins rebuild from source. See [Nix build layer](/architecture/nix-build).

2. **`default.nix`**: shim that returns the full distribution from the tree's `nix/inputs.nix`, which also wires the overlay, modules and checks.

3. **`module.nix`**: Home Manager module that runs the configuration as a user-session Emacs daemon (`services.emacsConfig`), with an `emacsclient` desktop entry and optional `EDITOR`/`VISUAL` setup. Runs under systemd; `services.emacsConfig.package` swaps in another configuration-shaped distribution.

### Development Layer

- **`devenv.nix`**: development shell, **tooling only**, with no `emacs` binary. It ships Nix tooling and linters (`nil`, `nixfmt`, `treefmt`, `statix`, `deadnix`), the language servers and CLIs the Elisp config shells out to, the docs toolchain, and the fonts the UI config probes. Build and launch the editor with `just run-built` (see [Launching Emacs](/usage/launching)).
- **`justfile`**: day-to-day recipes: `run-built` (build via Nix, then launch), `build`, `test`, `fmt`, `docs-refresh-packages`, `cache-parity`, `clean`. Elisp lint, compile, and test coverage comes from the `elisp-lint` / `elisp-compile` / `elisp-test` checks.
- **Pinning**: the tree's nixtamal pins (`nix/tamal/` at the repo root) are the single source of truth; `default.nix`, `emacs.nix`, and `overlay.nix` read them. Root `just update` bumps them.

# Nix Build System

Jotain builds Emacs with Nix, exposing the build options as arguments. nixpkgs comes from the revision pinned in `flake.lock`: `default.nix` and `emacs.nix` read it directly via `fetchTarball`, so non-flake `nix-build` consumers get the same pin. Pass `--arg pkgs '<nixpkgs>'` to use a different one.

## Two-Layer Architecture

### emacs.nix

The core build expression. It picks a base package per variant (emacs-overlay's `emacs-unstable` / `emacs-git` / `emacs-igc`, or nixpkgs' `emacs` for `mainline`) and calls `.override { ... }` with its arguments. The build matrix is four shipped builds on {x86_64, aarch64} × {Linux, Darwin}: pgtk/Wayland GUI or terminal-only on Linux, patched NS GUI or terminal-only on Darwin. `emacs.nix` asserts every other GUI configuration away. pgtk honors each backend's scale (Wayland fractional scale), so a fixed point size tracks the system. With `withPgtk = true` (the Linux GUI default) it selects the prebuilt `*-pgtk` sibling (`emacs-unstable-pgtk` etc.) instead of overriding `withPgtk` on the plain base: both build the same content, but only the sibling's store path is in the cache. [`nix-community/emacs-overlay`](https://github.com/nix-community/emacs-overlay) is a flake input composed into every overlay consumer in `flake.nix`; `emacs.nix` and `overlay.nix` re-apply it from `flake.lock` when imported standalone.

Supported:

- **Source variants**: `unstable` (the newest Emacs release or pretest tag, currently 31.1; the default), `git` (master), `igc` (the `feature/igc3` Memory Pool System GC branch), `mainline` (nixpkgs' `emacs`; the parity canary, not a flake output).
- **GUIs**: pgtk (the only Linux GUI), NS (the only macOS GUI, patched by default), or none (`noGui = true`).
- **Compilation**: native compilation (libgccjit AOT, on when the build platform can execute the host), compressed install, C sources for `find-function-C-source`, `srcRepo` (autoreconf on git sources), opt-in `useCcache`.
- **Image formats**: WebP (default), optionally ImageMagick.
- **Libraries**: tree-sitter, SQLite3, dbus, selinux, gpm, ALSA, ACL, mailutils, systemd, GLib networking. The overlay drops mailutils/gpm/selinux from the builds already off cache parity (both terminal-only builds and the Darwin GUI); the Linux pgtk build keeps upstream defaults so it stays identical to the cached `emacs-unstable-pgtk`.
- **Darwin patches**: `system-appearance`, `round-undecorated-frame`, and `fix-ns-x-colors`, applied via `overrideAttrs` and **on by default for the NS GUI**, so every Darwin GUI build is a from-source build. The Emacs 31/30 patch sets come from `nix-giant/nix-darwin-emacs`; the master set (the `git` / `igc` variants) from `d12frosted/homebrew-emacs-plus`, because nix-giant dropped its unstable patch branch.

### Cache-parity invariant

Every argument default in `emacs.nix` matches the corresponding default in nixpkgs' `make-emacs.nix` (and the explicit args emacs-overlay passes to its prebuilt attrs). As long as that holds,

```nix
import ./emacs.nix {}                          # unstable (bare-file default)
import ./emacs.nix { variant = "mainline"; }   # nixpkgs' emacs, the parity canary
import ./emacs.nix { noGui = true; }           # any standard override
```

produces the *exact* store path of the matching base attr. On Linux each GUI build maps to the prebuilt `*-pgtk` sibling (`emacs-unstable-pgtk`, `emacs-git-pgtk`, `emacs-igc-pgtk`, or nixpkgs' `emacs-pgtk` for `mainline`); `noGui` builds map to their own attrs. The `nix-community.cachix.org` (git/unstable/igc), Hydra (mainline), and `jylhis` caches therefore hit and nothing compiles from source. Custom `rev` pins, `useCcache`, `cpuTune`, and the Darwin patches go through `overrideAttrs` or a different stdenv and intentionally miss the cache.

Verify after any change to defaults:

```bash
nix-instantiate --eval --strict -E '
  let lock = builtins.fromJSON (builtins.readFile ./flake.lock);
      n  = lock.nodes.${lock.nodes.root.inputs.nixpkgs}.locked;
      ov = lock.nodes.${lock.nodes.root.inputs.emacs-overlay}.locked;
      nixpkgs = fetchTarball {
        url = "https://github.com/${n.owner}/${n.repo}/archive/${n.rev}.tar.gz";
        sha256 = n.narHash;
      };
      overlay = fetchTarball {
        url = "https://github.com/${ov.owner}/${ov.repo}/archive/${ov.rev}.tar.gz";
        sha256 = ov.narHash;
      };
      pkgs = import nixpkgs { overlays = [ (import overlay) (import ./overlay.nix) ]; };
  in {
    # On this x86_64-linux eval every GUI build maps to a *-pgtk sibling
    # (pgtk is the Linux GUI default in emacs.nix itself); non-pgtk Linux
    # GUIs are asserted away and cannot be evaluated.
    default       = pkgs.jotainEmacs.outPath == pkgs.emacs-unstable-pgtk.outPath;
    bare-default  = (import ./emacs.nix {}).outPath == pkgs.emacs-unstable-pgtk.outPath;
    mainline-pgtk = (import ./emacs.nix { variant = "mainline"; }).outPath == pkgs.emacs-pgtk.outPath;
    git-pgtk      = (import ./emacs.nix { variant = "git"; }).outPath == pkgs.emacs-git-pgtk.outPath;
    igc-pgtk      = (import ./emacs.nix { variant = "igc"; }).outPath == pkgs.emacs-igc-pgtk.outPath;
  }'
```

The override arg set is filtered through `lib.intersectAttrs (lib.functionArgs basePackage.override)`, so only flags the base `make-emacs.nix` defines are forwarded. A downstream flake that overrides `nixpkgs` with an older release (24.05+) therefore still evaluates: flags added in newer `make-emacs.nix` versions are dropped instead of failing with "called with unexpected argument". On the pinned unstable every argument is accepted, so the filter is a no-op and parity is unaffected.

### default.nix

A thin flake-compat wrapper. It reads the pinned `flake-compat` rev from `flake.lock`, evaluates `flake.nix`, and promotes the current system's packages to the top level: `nix-build` builds the full distribution (`jotainEmacsPackages`), `nix-build -A emacs` the bare Emacs. Variant builds target `emacs.nix` directly (e.g. `nix-build emacs.nix --arg variant '"git"'`).

### Tree-sitter grammars

Grammars are bundled in `nix/mk-overlay.nix`: the distribution's `withPackages` set includes `epkgs.treesit-grammars.with-all-grammars` (~275 grammars, a linkFarm over per-grammar derivations, so they cost closure size but not build time). nixpkgs' `site-start.el` points `treesit-extra-load-path` at the bundled directory, so `early-init.el` needs no `TREE_SITTER_DIR` handling. `init-prog.el` passes `treesit-extra-load-path` on to async native-comp workers, which run without site files.

### emacs-packages

`legacyPackages.<system>.emacs-packages` (`nix/emacs-package-set.nix`) exposes every Emacs package the configuration bundles, each individually buildable: the `lisp/` use-package scan with `:ensure` aliases resolved, the Nix-provided extras (`nix/nix-provided-packages.nix`), and the tree-sitter grammar set.

```bash
nix build .#emacs-packages.magit
nix build .#emacs-packages.treesit-grammars
```

Keys are use-package head names, so `dired-async` holds the `async` derivation its `:ensure async` resolves to. The set lives in `legacyPackages` so `nix flake check` never builds it; the eval-only `emacs-packages-eval` check verifies every name resolves to a derivation. It mirrors `packages.default` (the GUI build), not `emacs-nox`.

## Key Build Options

| Option | Default | Description |
|---|---|---|
| `variant` | `"unstable"` | Emacs source variant: `unstable` / `git` / `igc` / `mainline` |
| `noGui` | `false` | Terminal only (`--without-x --without-ns`) |
| `withPgtk` | `isLinux && !noGui` | Pure GTK (Wayland), the Linux GUI. Selects the prebuilt `*-pgtk` sibling for cache parity |
| `withNS` | `isDarwin && !noGui` | Cocoa/NeXTstep, the macOS GUI |
| `withNativeCompilation` | auto | libgccjit AOT compilation |
| `withTreeSitter` | `true` | Built-in tree-sitter support |
| `withSystemd` | Linux | `--with-systemd` (journal support) |
| `withSystemAppearancePatch` | `withNS` | (Darwin) `ns-system-appearance` hooks |
| `withRoundUndecoratedFramePatch` | `withNS` | (Darwin) rounded borderless frames |
| `withFixNsXColorsPatch` | `withNS` | (Darwin) refresh `x-colors` from `ns-list-colors` at runtime, so the full palette is available instead of the ~62 colors in the headless dump |
| `rev` / `hash` | `null` | Pin a specific commit for the `git` / `unstable` / `igc` variants |
| `useCcache` | `false` | Build with `pkgs.ccacheStdenv` (cache dir from `ccacheDir`, default `/var/cache/ccache`). Only for builds already off cache parity (custom `rev`, the Darwin GUI, `igc` on Darwin); needs an `extra-sandbox-paths` entry first |
| `cpuTune` | `null` | Appends `-O3 -march=<tune> -mtune=<tune>` to `NIX_CFLAGS_COMPILE` (`just build-perf` passes `icelake-client`). Off every binary cache by design |

See `emacs.nix` for the full argument list.

## IGC Variant

The `igc` variant builds Emacs's `feature/igc3` branch, which replaces the mark-and-sweep garbage collector with the [Memory Pool System](https://memory-pool-system.readthedocs.io). emacs-overlay's `emacs-igc` already carries `--with-mps=yes` and the `mps` input, and on Linux the default revision is a binary-cache hit. `nix-community.cachix.org` has no Darwin `emacs-igc`, so `just build-igc` compiles from source there; `just build-igc-ccache` makes repeat rebuilds cheaper once ccache is set up (see the `useCcache` comment in `emacs.nix`).

## Git Variants

`git`, `unstable`, and `igc` build the revision pinned inside emacs-overlay (advanced here by `just update`) and are cache hits from `nix-community.cachix.org`. To pin another commit, pass `--argstr rev "..."`: `emacs.nix` fetches it from `https://git.savannah.gnu.org/git/emacs.git`, and the first build reports the hash to pass back via `--argstr hash "sha256-..."`. `postPatch` then writes the revision into `lisp/loadup.el` so `emacs-repository-get-version` works without a `.git` directory. The overlay's `--enable-check-lisp-object-type` on `aarch64-linux` (it avoids segfaults there) carries over to custom revisions.

## nix-on-droid

`nixOnDroidModules.default` (`module-nix-on-droid.nix`) installs Jotain on Android via [nix-on-droid](https://github.com/nix-community/nix-on-droid). Android runs headless under proot, so the module is a trimmed `module-system.nix`: it `pkgs.extend`s the overlay and adds a **terminal-only** build (`jotainEmacsPackagesNoGui`) plus an `emacsclient` `EDITOR`/`VISUAL` wrapper via `environment.packages` and `environment.sessionVariables`. There is no systemd service, launchd agent, `fonts.packages`, or GUI.

`flake.nix` also exposes an example `nixOnDroidConfigurations.default` (aarch64-linux). It only activates on a device or under aarch64 emulation, so `nix flake check` does not realise it; the module is eval-checked on x86_64 by `nix-on-droid-module-eval`.

## Overriding nixpkgs

A downstream flake can follow a different nixpkgs (release branches **24.05+** through unstable):

```nix
inputs.jotain.inputs.nixpkgs.follows = "nixpkgs";
```

The argument filter described under [Cache-parity invariant](#cache-parity-invariant) keeps the modules evaluating and building on older releases. The caveat is the Emacs version: 24.05's `pkgs.emacs` is Emacs 29, while Jotain's Elisp targets 30/31, so the build succeeds but runtime behaviour is only guaranteed on the pinned unstable.

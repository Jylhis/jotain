# Nix Build System

This configuration builds Emacs with Nix, exposing the build options as arguments. nixpkgs comes from the tree's nixtamal pins (`nix/tamal/` at the repo root): `default.nix` and `emacs.nix` read them through `nix/inputs.nix`. Pass `--arg pkgs '<nixpkgs>'` to use a different one.

## Two-Layer Architecture

### emacs.nix

The core build expression. It picks a base package per variant (emacs-overlay's `emacs-unstable` / `emacs-git` / `emacs-igc`, or nixpkgs' `emacs` for `mainline`) and calls `.override { ... }` with its arguments. The build matrix is two shipped builds on {x86_64, aarch64} Linux: pgtk/Wayland GUI or terminal-only. `emacs.nix` asserts every other GUI configuration away. pgtk honors each backend's scale (Wayland fractional scale), so a fixed point size tracks the system. With `withPgtk = true` (the Linux GUI default) it selects the prebuilt `*-pgtk` sibling (`emacs-unstable-pgtk` etc.) instead of overriding `withPgtk` on the plain base: both build the same content, but only the sibling's store path is in the cache. [`nix-community/emacs-overlay`](https://github.com/nix-community/emacs-overlay) is a flake input composed into every overlay consumer in `flake.nix`; `emacs.nix` and `overlay.nix` re-apply it from `flake.lock` when imported standalone.

Supported:

- **Source variants**: `unstable` (the newest Emacs release or pretest tag, currently 31.1; the default), `git` (master), `igc` (the `feature/igc3` Memory Pool System GC branch), `mainline` (nixpkgs' `emacs`; the parity canary, not a flake output).
- **GUIs**: pgtk (the only GUI), or none (`noGui = true`).
- **Compilation**: native compilation (libgccjit AOT, on when the build platform can execute the host), compressed install, C sources for `find-function-C-source`, `srcRepo` (autoreconf on git sources), opt-in `useCcache`.
- **Image formats**: WebP (default), optionally ImageMagick.
- **Libraries**: tree-sitter, SQLite3, dbus, selinux, gpm, ALSA, ACL, mailutils, systemd, GLib networking. The overlay drops mailutils/gpm/selinux from the builds already off cache parity (the terminal-only builds); the Linux pgtk build keeps upstream defaults so it stays identical to the cached `emacs-unstable-pgtk`.

### Cache-parity invariant

Every argument default in `emacs.nix` matches the corresponding default in nixpkgs' `make-emacs.nix` (and the explicit args emacs-overlay passes to its prebuilt attrs). As long as that holds,

```nix
import ./emacs.nix {}                          # unstable (bare-file default)
import ./emacs.nix { variant = "mainline"; }   # nixpkgs' emacs, the parity canary
import ./emacs.nix { noGui = true; }           # any standard override
```

produces the *exact* store path of the matching base attr. On Linux each GUI build maps to the prebuilt `*-pgtk` sibling (`emacs-unstable-pgtk`, `emacs-git-pgtk`, `emacs-igc-pgtk`, or nixpkgs' `emacs-pgtk` for `mainline`); `noGui` builds map to their own attrs. The `nix-community.cachix.org` (git/unstable/igc), Hydra (mainline), and `jylhis` caches therefore hit and nothing compiles from source. Custom `rev` pins, `useCcache`, and `cpuTune` go through `overrideAttrs` or a different stdenv and intentionally miss the cache.

Verify after any change to defaults:

```bash
just cache-parity   # nix/cache-parity.nix: every value must be true
```

The override arg set is filtered through `lib.intersectAttrs (lib.functionArgs basePackage.override)`, so only flags the base `make-emacs.nix` defines are forwarded. A consumer whose `pkgs` is an older release (24.05+) therefore still evaluates: flags added in newer `make-emacs.nix` versions are dropped instead of failing with "called with unexpected argument". On the pinned unstable every argument is accepted, so the filter is a no-op and parity is unaffected.

### default.nix

A shim over the tree's `nix/inputs.nix`: `nix-build` builds the full distribution (`emacsConfigPackages`). Bare and variant builds target `emacs.nix` directly (e.g. `nix-build emacs.nix --arg variant '"git"'`).

### Tree-sitter grammars

Grammars are bundled in `nix/mk-overlay.nix`: the distribution's `withPackages` set includes `epkgs.treesit-grammars.with-all-grammars` (~275 grammars, a linkFarm over per-grammar derivations, so they cost closure size but not build time). nixpkgs' `site-start.el` points `treesit-extra-load-path` at the bundled directory, so `early-init.el` needs no `TREE_SITTER_DIR` handling. `init-prog.el` passes `treesit-extra-load-path` on to async native-comp workers, which run without site files.

### emacs-packages

`nix/emacs-package-set.nix` resolves every Emacs package the configuration bundles, each individually buildable: the `lisp/` use-package scan with `:ensure` aliases resolved, the Nix-provided extras (`nix/nix-provided-packages.nix`), and the tree-sitter grammar set.

Keys are use-package head names, so `dired-async` holds the `async` derivation its `:ensure async` resolves to. Nothing builds the set as a whole; the eval-only `emacs-packages-eval` check verifies every name resolves to a derivation. It mirrors `packages.default` (the GUI build), not `emacs-nox`.

## Key Build Options

| Option | Default | Description |
|---|---|---|
| `variant` | `"unstable"` | Emacs source variant: `unstable` / `git` / `igc` / `mainline` |
| `noGui` | `false` | Terminal only (`--without-x --without-ns`) |
| `withPgtk` | `isLinux && !noGui` | Pure GTK (Wayland), the Linux GUI. Selects the prebuilt `*-pgtk` sibling for cache parity |
| `withNativeCompilation` | auto | libgccjit AOT compilation |
| `withTreeSitter` | `true` | Built-in tree-sitter support |
| `withSystemd` | Linux | `--with-systemd` (journal support) |
| `rev` / `hash` | `null` | Pin a specific commit for the `git` / `unstable` / `igc` variants |
| `useCcache` | `false` | Build with `pkgs.ccacheStdenv` (cache dir from `ccacheDir`, default `/var/cache/ccache`). Only for builds already off cache parity (custom `rev`); needs an `extra-sandbox-paths` entry first |
| `cpuTune` | `null` | Appends `-O3 -march=<tune> -mtune=<tune>` to `NIX_CFLAGS_COMPILE` (e.g. `icelake-client`). Off every binary cache by design |

See `emacs.nix` for the full argument list.

## IGC Variant

The `igc` variant builds Emacs's `feature/igc3` branch, which replaces the mark-and-sweep garbage collector with the [Memory Pool System](https://memory-pool-system.readthedocs.io). emacs-overlay's `emacs-igc` already carries `--with-mps=yes` and the `mps` input, and the default revision is a binary-cache hit. `--arg useCcache true` makes repeat rebuilds cheaper once ccache is set up (see the `useCcache` comment in `emacs.nix`).

## Git Variants

`git`, `unstable`, and `igc` build the revision pinned inside emacs-overlay (advanced by `just update` at the repo root) and are cache hits from `nix-community.cachix.org`. To pin another commit, pass `--argstr rev "..."`: `emacs.nix` fetches it from `https://git.savannah.gnu.org/git/emacs.git`, and the first build reports the hash to pass back via `--argstr hash "sha256-..."`. `postPatch` then writes the revision into `lisp/loadup.el` so `emacs-repository-get-version` works without a `.git` directory. The overlay's `--enable-check-lisp-object-type` on `aarch64-linux` (it avoids segfaults there) carries over to custom revisions.

## nix-on-droid

`module-nix-on-droid.nix` installs the configuration on Android via [nix-on-droid](https://github.com/nix-community/nix-on-droid). Android runs headless under proot, so the module is a trimmed `module-system.nix`: it `pkgs.extend`s the overlay and adds a **terminal-only** build (`emacsConfigPackagesNoGui`) plus an `emacsclient` `EDITOR`/`VISUAL` wrapper via `environment.packages` and `environment.sessionVariables`. There is no systemd service, `fonts.packages`, or GUI.

The module is not exported from `nix/inputs.nix`; import the file by path. It is eval-checked on x86_64 by `nix-on-droid-module-eval`.

## Older nixpkgs

The modules use the importing configuration's `pkgs` (release branches **24.05+** through unstable).

The argument filter described under [Cache-parity invariant](#cache-parity-invariant) keeps the modules evaluating and building on older releases. The caveat is the Emacs version: 24.05's `pkgs.emacs` is Emacs 29, while the configuration's Elisp needs 31.1, so the build succeeds but runtime behaviour is only guaranteed on the pinned unstable.

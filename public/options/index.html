Jotain — Module Options Reference

Auto-generated reference for all Nix module options exposed by Jotain.

  • Home Manager Module — per-user Emacs daemon, client wrapper, desktop entry
  • System Module — overlay and system packages
  • devenv Module — Emacs Lisp development environment

Home Manager Module

Import and enable in your Home Manager configuration:

{
  imports = [ jotain.homeManagerModules.default ];
  services.jotain = {
    enable = true;
    defaultEditor = true;
    client.enable = true;
  };
}

services.jotain.authSources

Extra authinfo/netrc file paths to hand to Emacs’s auth-sources, searched ahead of ~/.authinfo(.gpg) and the 1Password backend. Point these at runtime secret files a secret manager produces (sops-nix, agenix, …) — the entries are file paths, not the secrets themselves, and are passed to the daemon through the JOTAIN_AUTH_SOURCES environment variable that lisp/init-systems.el reads. Every package that consults auth-source (gptel, forge, smtpmail, circe) then resolves credentials from them; the eca server, which reads only its environment, additionally has its provider keys exported from auth-source before each session (see lisp/init-ai.el).

Type: list of string

Default:

[ ]

Example:

[
  "/run/secrets/authinfo"
]

services.jotain.eca.openrouter.enable

Whether to enable the default OpenRouter provider in the generated eca config. The provider and its model catalogue come from config/eca/config.json (kept in sync with gptel’s models in lisp/init-ai.el); the API key is read at runtime from OPENROUTER_API_KEY via eca’s ${env:…} interpolation, so no secret is written to the Nix store. Supply the key through services.jotain.environmentFile. gptel defaults to OpenRouter regardless of this option .

Type: boolean

Default:

false

Example:

true

Declared by: - module.nix

services.jotain.eca.settings

Freeform eca configuration, rendered to ~/.config/eca/config.json and deep-merged over the default OpenRouter provider (later values win). Any eca key is expressible (providers, models, rules, mcpServers, behavior, …). Use eca’s ${env:VAR} syntax for secrets so nothing sensitive lands in the Nix store; provide the referenced variables through services.jotain.environmentFile.

Type: JSON value

Default:

{ }

Example:

{
  providers.anthropic = {
    api = "anthropic";
    key = "${env:ANTHROPIC_API_KEY}";
    models."claude-sonnet-4.6" = { };
  };
}

services.jotain.environmentFile

Path to a systemd.exec(5)-style environment file (VAR=value lines) loaded into the Jotain daemon’s environment. Every subprocess Emacs spawns inherits it, so this is the single place to supply credentials for all external-system integrations that read the environment — among them gptel’s OPENROUTER_API_KEY / ANTHROPIC_API_KEY / GEMINI_API_KEY (lisp/init-ai.el), the eca server’s provider keys, and any token a tool reads from the environment. Point it at a runtime secret path (sops-nix, agenix, …); the file is read at daemon start and never copied into the Nix store. On Linux it becomes the service’s EnvironmentFile; on macOS the launchd agent sources it before exec. Secrets that instead live in a password manager can be resolved through auth-source — see services.jotain.onePassword.enable and services.jotain.authSources.

Type: null or absolute path

Default:

null

Example:

"/run/secrets/jotain-env"

services.jotain.nativeCompile.enable

AOT native-compile the Jotain config into the store, so the daemon loads .eln for init.el and the lisp/ modules from services.jotain’s own derivation instead of JIT-compiling into var/eln-cache after every deploy (every deploy that touches lisp/ moves the store path, which invalidates the JIT cache). early-init.el is structurally excluded: its .eln lookup happens before the load path is extended, so it always runs from .elc — with or without this option.

The store-.eln-through-symlinks mechanism is sound: Emacs realpath()s the source before hashing it into the .eln name (src/comp.c, Bug#44701), so the HM symlinks resolve to the exact path the AOT step compiled against. Off by default only because enabling it adds a native-compilation pass to every activation that rebuilds the config, and roughly 50–150 MB of .eln to the closure.

Type: boolean

Default:

false

Example:

true

Declared by: - module.nix

System Module (NixOS / nix-darwin)

Applies the Jotain overlay and adds the package to system environment. For per-user daemon management, use the Home Manager module instead.

{
  imports = [ jotain.nixosModules.default ];  # or darwinModules.default
  services.jotain.enable = true;
}
